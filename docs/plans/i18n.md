# Korean, English, and Simplified Chinese plan

Every screen of Video Gen Studio is Korean today. After this program, a member reads the whole site in Korean, English, or Simplified Chinese.
The language starts from the browser, can be switched on the login screen and in 설정, and follows the member to every device. URLs do not change.
Korean stays the source. Model names and user content (prompts, nicknames, team names, IDs) are never translated.
The rule the program enforces is that no UI file holds Korean text. `npm run lint` fails on a Hangul literal in `src/`, and `npm run i18n:check` fails when the three message files disagree.
The library is next-intl 4.14.9 without locale routing. Server errors travel as codes that the browser translates.
The work units are I18N-1 (foundation and sign-in), I18N-2 (member language and shell), I18N-3 (error codes), I18N-4 (formatting), I18N-5 (gallery and dashboard), I18N-6 (playground), I18N-7 (settings, members, teams), I18N-8 (import, models, logs), and I18N-9 (close the guard, apply review).
The operator chose to deliver them as five PRs, in this order. Each PR carries the boxes of its units.

**PR 1 as built.** Where it differs from the I18N-1 and I18N-2 sections below, the code is the record.

- One route sets the language. `POST /api/locale` always sets the cookie and, for a signed-in member, also writes `users.locale`. `PATCH /api/me` is unchanged, and `LanguagePicker` has one mode.
- `src/i18n/locale.ts` holds the shared-browser rule as `localeAfterSignIn({ picked, stored })`. Both `POST /api/auth/login` and `POST /api/auth/password` call it, because a new member's first sign-in ends in the forced password change. "Picked during this visit" means picked in the login page's React state, so a reload of that page starts a new visit.
- Page names live in one `pages` namespace that the header links and the tab titles share (`pageTitle()` in `src/i18n/metadata.ts`). The close button is `common.close`.
- The check logic is `src/i18n/check.ts` with `src/i18n/check.test.ts`. `scripts/i18n-check.mts` only reads the files. The unit test command gains `src/i18n/*.test.ts`.
- `scripts/i18n-selectors.mts` and `scripts/i18n-review.mts` are not built. PR 1 converted its 40 or so selectors by hand, and the operator reviews screenshots. PR 3, which owns most of the 203 Korean selectors, builds the selector script if it still pays.
- Measured on `next start` builds of `d33a8fe` and the PR head, three identical runs each. `/login` scripts went from 137.7 to 141.1 KB gzip (460.5 to 470.3 KB raw). Inline flight data went from 5.5 KB to 7.7 KB (ko) and 8.6 KB (en), because the provider sends the whole catalog. That cost grows with every PR's messages.

**PR 2 as built.** Where it differs from the I18N-3 and I18N-4 sections below, the code is the record.

- A failure reason is a `Reason`, either an `AppError` (`{ code, params }`) the page translates or `{ text }` shown as written (provider words, a reason stored before `0010`, a message thrown in the browser). `publicGeneration` returns it as `reason`, for failed rows and for a pending row's wait reason alike.
- `0010_generation_error_code` adds two nullable columns, `error_code` and `error_params` (`jsonb`), because several reasons carry values (minutes, provider detail, the cause of an unanswered image call). `error` keeps provider text and old Korean text. `generations.ts` writes the three together through one helper, and a pending row "has a reason" when either form is set.
- `parseAppError(body, status)` takes the HTTP status, so a body without a code (a proxy's page, a server from before codes) reads as `httpStatus`. A code the page has no message for reads as `unknownCode` in `reasonText`, which checks `t.has`. `ApiError` and `caught()` carry an `AppError` through a browser `catch`.
- `planGeneration`'s blocker is an `AppError`. Its mode is a `select` over mode ids in the message. Its param label is passed as a value, still Korean until PR 3 translates the catalog's labels.
- Every lib that fed `HttpError` a sentence now returns an `AppError`, so `display-name.ts`, `nickname.ts`, `teams.ts`, `member-import.ts` and `model-settings.ts` also left `I18N_PENDING`. `particle()` is gone; each name message selects on `kind`.
- `now` is not in `request.ts`. The root layout's provider survives client navigations, so a `now` there would go stale. The gallery page passes its own render time (`getNow()`) to the tiles instead.
- A 401 or 403 from OpenAI keeps the code `openaiKeyRejected` and also carries OpenAI's own message, redacted, with its `code` and `type` as `params.detail`, because only those words say whether the key, an IP, an organization, a scope or a region was refused. The operator asked for it after a production failure that showed only the Korean sentence.
- `usd()` keeps no digit grouping (`$1234`), so the Korean dashboard reads as before. The gallery's 보관 line (`expiresIn`, "N일 남음") stays for PR 3 with the rest of the gallery's text.

**PR 3 as built.** Where it differs from the I18N-5 and I18N-6 sections below, the code is the record.

- The catalog holds no words. `Family.key` (`seedance`, `h3`, `gptImage2`) names a family in the messages, because a next-intl key cannot hold the "." in `bytedance/seedance-2.0`. Parameter labels are `params.<key>`, enum option labels `paramValues.<key>` (one ICU `select` per parameter), blurbs and notes `families.<key>.*`, the rate's basis, unit, presets and example `prices.*`, and modes `mode.<Mode>`. `rate.per` became `rate.unit` (`second` or `mTokens`), presets became `PricePreset`, `rate.example` is the `CostBasis` itself, and `facts()` returns a `Fact` union the page words.
- `modelLine(modelId, modeName)` takes the mode translator. `describeModel` lost `paramLabel`; any page reads a stored key through `useParamLabel()`, which shows an unknown key (a stored `seed`) as itself.
- A parameter blocker carries the key on the wire as `params.param`. `reasonText(t, reason, paramLabel)` fills `label` in the page language, so `errors.paramRange|paramChoice|paramOnOff` keep `{label}`.
- Two namespaces the plan did not name. `generation` holds the words for one result row that the gallery and the playground share (no prompt, generated video or image, download, the reference names, the shape `select`). `paramValues` holds the option labels. The reference dialog's note is one `select` over the provider in `playground.refs.note`, not a message per family.
- The root layout sends only `SHARED` (`pages`, `common`, `nav`, `status`, `language`, `auth`, `errors`, `params`), from `sharedMessages()` in `src/i18n/provider.tsx`. The gallery, playground and admin pages pass `pageMessages([...])` to their own `NextIntlClientProvider`; the dashboard renders on the server and needs none. React sends a namespace two providers share once, as a reference. A first version wrapped the root's children in a separate async component, which delayed the new `<title>` after a language pick; the Korean `locale` journey caught it.
- Korean wording changes, all small. The first-frame note reads `… 정사각 이미지라 영상도 정사각으로 나옵니다` and adds "가로 영상이 필요하면 …" only when the image is not landscape. A full image drop zone reads `이미지 N장 모두 추가됨`. The video hint reads `mp4 · 200 MB 이하`. A wrong file type names the accepted types. The empty-prompt tile is named `(프롬프트 없음) 자세히 보기`. Counts of 1,000 or more print with grouping (`1,234회`).
- `scripts/seed.ts` no longer writes the Korean blurb into `models.note`, which no screen shows.
- `scripts/i18n-selectors.mts` and the `i18n-review.mts` workbook were not built. The six swept journeys were converted by hand. `journeys/screens.mjs` folds the twenty live lanes of I18N-5 and I18N-6 into one run per language and viewport and saves the review images to `.impeccable/review/i18n-3/`.

Measured on `287f1d9` and the PR head against one local database with the admin's 40 `[목업]` rows, one round each because the counts repeat to the byte (two trunk rounds were identical). ## Appendix B. Alternatives rejected

- An in-house dictionary. It saves about 3 KB gzip on the login page against precompiled next-intl. It would also need ICU `select` for the closed-set particles, `plural` for 61 counter strings, rich text for 14 sentences, typed arguments, a request-scoped locale getter, and a provider. next-intl already has all of these, and the spike shows them working on this app's Next version. Writing them again is the larger and riskier diff.
- Server-side translation by request locale. The server would have to resolve the member's locale inside every route handler, where React `cache()` does not share the `users` row, and API responses would change with the viewer. Codes keep the server free of locale state, let the same `Blocker` drive the cost bar and the 400, and match the refusal codes the spend-cap program needs.
- A cookie alone for the member preference. It does not follow a member to a second device or browser, which the operator asked for, and on a shared browser one member's choice would become the next member's. The column costs one nullable field and no extra query, because the root layout and the `(app)` layout share the cached `users` row.
- Locale prefixes in URLs (`/en/...`). The operator ruled them out. They would also move every route under `app/[lang]`.
- Pinning journeys to Korean. The seeded admin account that most journeys use could carry any preference once members can choose. Key lookups through `ev.t` pass in any language and let every sweep PR run its journeys in all three.
- `data-testid` handles. They would drop the check that accessible names exist and make sense, which is part of what the journeys prove today.
- A Korean particle library. Closed sets get ICU `select` and open values are rephrased, which the repository already did in `fe85c49`. A library would guess at model names and numbers, such as `Kling 3.0`, and the check rejects the pattern instead.
- A web font for Chinese (`Noto Sans SC` through `next/font`). The design already relies on system fonts for Hangul, and every target system ships a Simplified Chinese gothic. A CJK web font adds megabytes for a 20-person team.
- next-intl `useExtracted`. It writes source text inline and extracts keys automatically, which suits agents. It is experimental, and it would make Korean literals legal in components again, which defeats the guard.
- One message file per namespace to avoid merge conflicts. The `precompile` loader infers locales from file names, and the spike did not test nested files. A linear stack and namespace ownership keep conflicts rare.

## Appendix C. Risks

- `experimental.messages.precompile` changes in a next-intl minor release. The I18N-1 owner pins `4.14.9` exactly. If a later upgrade breaks it, set `precompile: false` (+8.7 KB gzip measured) in one line.
- Chinese and English quality without a native reviewer. Each review gate includes a cross-model translation audit and a workbook, and I18N-9 applies the named reviewers' fixes. If nobody reads Chinese, the operator decides whether to ship zh-CN as agent-drafted (Appendix G, decision 1).
- English is longer than Korean. Narrow rows (the mobile `주 메뉴`, aspect pills, rail glyph labels, table headers) may overflow. Every sweep PR has a 390 px lane that checks `scrollWidth`.
- Han unification in user content. A Chinese prompt viewed in the Korean UI still renders with Korean fonts, because the app does not know a prompt's language. UI text is correct in every locale.
- Merge conflicts in the message files when TEAM-2 and TEAM-3 run beside I18N-6 to I18N-9. Each PR edits only its own namespaces, and `npm run i18n:check` after a rebase catches a lost key.
- Old failure reasons stay Korean in `generations.error`. They appear only on old failed rows in the playground feed and 어드민 로그.
- Migrations `0009` and `0010` run against the shared database that production uses. Both add one nullable column. The I18N-2 and I18N-3 owners apply them once and watch `npm run db:migrate` output.
- `npm run typecheck` runs `tsc` without the generated `ko.d.json.ts`, so it checks keys but not arguments. `npm run build` checks both, and Vercel runs it. Each owner runs `npm run build` once before the PR-facing push.
- `next dev` rewrites its own block in `AGENTS.md`. The I18N-1 owner writes the Internationalization section outside that block.
- A member outside Seoul time sees Seoul times. The default is a fixed `Asia/Seoul` (Appendix G, decision 2).
- The `i18n:check` particle rule flags `이`, which also starts words like `이 팀을`. The rule checks only text right after a placeholder, and the owner rephrases a false hit.

## Appendix E. Design reference

**Library.** next-intl 4.14.9 without i18n routing, with `precompile` and `createMessagesDeclaration`.

| Criterion | next-intl, no routing | In-house dictionary |
|---|---|---|
| Server and Client Components | `getTranslations` in async server code, `useTranslations` in both, and the provider passes messages down | A server getter, a client context, and the provider, written by us |
| Next 16 | The peer range includes `^16.0.0`, and the spike built and ran on 16.4.3 with Turbopack | No dependency |
| Plurals, select, numbers, dates, rich text | ICU messages, `useFormatter`, a configured time zone and `now` | Interpolation and plural only, unless we write the rest |
| Particles after a value | ICU `select` for closed sets, rephrasing for open values | The same, with a `select` we write |
| Client bundle on `/login` | +3.3 KB gzip measured with `precompile`, +12.0 KB without | About +0.3 KB gzip estimated |
| Typed keys and arguments | `AppConfig`, and `next build` fails on a bad key or a missing argument | Keys through `typeof ko`, arguments untyped |
| Locale on the server | `getRequestConfig` runs once per request, and `getLocale` works in any server code | A `cache()`d getter, written by us |
| Install | 13.1 MB at build time | None |

**Locale model.** Three locales, `ko`, `en`, and `zh-CN`, in `src/i18n/locale.ts`. One pure function decides.

1. The signed-in member's `users.locale`, when set.
2. The `vgs_locale` cookie, when it holds a known locale.
3. The first supported language in `Accept-Language` by q value. `ko-*` gives `ko`, `en-*` gives `en`, and any `zh-*` gives `zh-CN`.
4. `ko`.

`<html lang>` is the resolved locale (`ko`, `en`, or `zh-CN`). The cookie is never written from `Accept-Language`, so a cookie always records a choice. Three routes write it. `POST /api/locale` sets it for a visitor. `PATCH /api/me` sets it with `users.locale` for a member. `POST /api/auth/login` mirrors the member's stored locale into it after sign-in, and stores the login-screen choice in `users.locale` only when the visitor used the picker during that visit. That last rule keeps a shared browser's cookie from overwriting the next member's choice. The `users` row comes from `getCurrentUser`, wrapped in React `cache()`, so the locale costs no extra query.

**Messages.** `src/messages/ko.json` is the source. Keys are English camelCase, nested by surface namespace (`auth`, `nav`, `meta`, `language`, `status`, `errors`, `gallery`, `dashboard`, `playground`, `mode`, `params`, `families`, `prices`, `settings`, `admin`, `members`, `teams`, `import`, `models`, `logs`). A key names its purpose (`submit`, `lead`, `emptyTitle`), not its Korean text. Values are ICU messages.

- Use an argument for every value, never string concatenation, so a translator can reorder the sentence.
- Use `plural` for every count. Korean and Chinese need only `other`, and English needs `one` and `other`.
- Use `select` when a value is a closed set (status, mode, orientation, name kind), so each branch carries its own Korean particle.
- After an open value (a model name, a number, a nickname), write Korean that does not need a batchim-dependent particle. `{model}에는` and `모델 {model}` work, and `{model}을` does not. `npm run i18n:check` rejects the last form.
- Use `t.rich` for a sentence with a link or emphasis inside it.
- Write text no member sees (log lines, cron guard text) in English, outside the message files.

**Error codes.** The wire format is `{ "error": { "code": ErrorCode, "params"?: {...} } }`. `ErrorCode` is the key set of `errors` in `ko.json`, so a code without a message fails `tsc`. `HttpError(status, code, params?)` is the only way to send one. `parseAppError` parses a response at the client boundary. `useErrorText()` renders it in the page language. App failure reasons on a generation row live in `generations.error_code`, and provider text stays in `generations.error`, untranslated, like other content the app does not write.

**Formatting.** Dates and times use the configured `Asia/Seoul` with `dateStyle: "short"`, `timeStyle: "short"`, and `hourCycle: "h23"`. Relative times use `format.relativeTime` against the request's `now`. Dollars use `Intl.NumberFormat` with `currencyDisplay: "narrowSymbol"` and today's digits rule. Bebas counters stay numerals.

**Fonts.** Latin and digits stay Inter in every locale, and numerals stay Bebas Neue. Korean keeps today's stack. For Chinese, `globals.css` adds this rule, which lists Simplified Chinese system fonts before the Korean ones so Han characters do not mix fonts, and keeps the Korean fonts after them for Hangul nicknames and prompts.

```css
:root:lang(zh-CN) body {
	font-family: var(--font-sans), "PingFang SC", "Microsoft YaHei", "Noto Sans SC", "Noto Sans CJK SC", "Source Han Sans SC",
		"Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", ui-sans-serif, system-ui, sans-serif;
}
:lang(zh-CN) .break-keep {
	word-break: normal;
}
```

`DESIGN.md` Typography records both, and the Bebas rule gains one sentence. Bebas carries numerals and one Latin word in every locale, never Chinese.

**Harness.** Every browser context gets `locale: VGS_LOCALE ?? "ko-KR"`. `ev.t(key, values)` formats the message from the file that matches the page's `<html lang>`, with `createTranslator` from `use-intl/core`. A journey for a swept surface names elements only through `ev.t`, so it passes in all three languages. A journey for an unswept surface keeps its Korean literals, which still match because that surface is Korean in every locale. `scripts/i18n-selectors.mts` converts selectors when a surface is swept. `journeys/locale.mjs` covers the visitor picker, the cookie, browser-language detection, the member preference across contexts, logout, and the shared-browser rule, with its own `vgs-loc-*` members.

**Guard.** The local ESLint rule `i18n/no-hangul` reports any `Literal`, `JSXText`, or `TemplateElement` with Hangul under `src/`, except tests, `src/messages/`, and the files in `I18N_PENDING`. The list starts with every unswept file. Each sweep PR deletes its files from the list, and I18N-9 deletes the list. A new file is checked from the day it is created, so TEAM-2, TEAM-3, and the spend-cap program cannot add Korean literals. `npm run i18n:check` keeps the three message files in step.

## Appendix F. Translation workflow and glossary

**Who writes what.** Korean is the source. The PR owner, an agent, writes the Korean message first, then drafts English and Simplified Chinese in the same PR with `src/messages/glossary.md` open. A PR never lands with a key missing from a locale, because `npm run i18n:check` fails.

**How quality is checked.** Three layers check translations.

1. `npm run i18n:check` catches missing keys, dropped or renamed arguments, Hangul left in `en.json` or `zh-CN.json`, and Korean particles after open values.
2. The translation audit lane at every review-gated PR runs on a model other than the owner's. It reads the PR's messages with the glossary and the screenshots in all three languages. It reports mistranslations, terms that drift from the glossary, text that a screenshot shows clipped, and strings that read as machine translation, each with the key.
3. The operator reviews the screenshots and the workbook in chat. Reviewers the operator names fill the `en fix` and `zh-CN fix` columns of the workbook, and `npx tsx scripts/i18n-review.mts apply <file>` writes them back.

**What the AGENTS.md section says.** The judgment rules only. Keep the glossary terms. Write a key for purpose, not for its Korean. Write natural English and natural Mainland Simplified Chinese, not word-for-word. Keep model names and user content as they are. Everything else is a check.

**Never translated.** `Video Gen Studio`, `Higgsfield`, `OpenAI`, model names (`Seedance 2.0`, `MiniMax H3`, `Hailuo 2.3 Standard`, `GPT-image-2`), the `ADMIN` badge, `MP4`, resolution and ratio tokens (`480p`, `16:9`), Bebas counters (`5S`), prompts, nicknames, IDs, team names, file names, provider error text, and `[목업]` rows.

## Appendix G. Operator decisions

Each PR applies the default until the operator says otherwise in chat.

1. Who reviews English and Chinese? Default. The cross-model audit lane checks every gated PR, and the operator reviews screenshots. If no team member reads Chinese, zh-CN ships as agent-drafted and audited. The operator could instead name a reviewer for each language, and I18N-9 then waits for their workbook.
2. Which time zone do dates use? Default. `Asia/Seoul` for everyone, because the team works in Seoul. If some members work elsewhere, the operator could ask for each member's browser time zone instead, stored the same way as the language.
3. What does a Traditional Chinese browser (`zh-TW`, `zh-HK`) get? Default. Simplified Chinese, because it is closer for a Chinese reader than Korean. The operator could ask for Korean instead.
4. Should old failed rows be rewritten to codes? Default. No. Old rows keep their Korean reason. The operator could approve a one-time `update` that maps the five known Korean reasons to codes. That changes data, so it needs the operator's go.
5. The glossary terms in Appendix F, especially 作品库 for 갤러리, 创作台 for 플레이그라운드, and `member` for both 회원 and 사용자. Default. The table as written.
6. Should member import accept English or Chinese column headers? Default. No change. Headers already accept `nickname` and `email` beside `닉네임` and `이메일`.
